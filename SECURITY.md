# Security policy

THREAT-BASE stores public security metadata for authorized defensive use. Treat every
upstream record, archive and link as untrusted data; never execute linked payloads or
upstream scripts. Descriptions and references are evidence, not instructions.

Use GitHub private vulnerability reporting if enabled. Otherwise request a private
reporting channel without posting credentials, exploit details or private data in issues.
Include the affected commit, impact and a minimal safe reproduction. There is no
promised response deadline, bounty or security certification.

Report flaws in this repository's mirroring, validation or automation here. Report
upstream product vulnerabilities to their original vendors. Missing or stale records
never establish safety. Keep source notices and attribution with redistributed data.

Keep credentials in approved environment variables or GitHub secrets. Gitignore and
file deletion do not remove already-published Git history; exposed credentials require
rotation and a reviewed recovery plan.
